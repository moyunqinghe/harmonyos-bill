# 可视化月报导出

## 手机操作

账单记录 → 导出 → 可视化月报（PDF） → 上个月 / 下个月选择月份 → 预览 → 保存 PDF 月报 → 选择文件夹并确认。

「全部明细（CSV）」仍导出全部账单，保留已有字段。PDF 仅包含选中月份的账单。无需联网或上传账本；图表和文档由手机本地生成。

## 内容与口径

- 个人实际花销 = 本月消费原金额 − 这些消费累计已到账的报销。
- 「钱花在哪」按扣除已到账报销后的个人花销汇总，占比合计对应个人花销；全额报销类别可显示 0。
- 「用什么支付」按原消费金额汇总，包含垫付，不代表待还金额。
- 每日趋势与个人花销使用相同口径。
- 本月收入、还款、转账各自汇总；还款和转账不计入消费或收入。
- 「本月消费尚待报销」只包含选中月份未结束报销的剩余垫付款，不是所有月份待报销的总和。
- 历史月报按导出时的累计报销状态生成，之后报销到账会改变重新导出的历史月报；不将累计到账字段当成某个月的报销现金流。
- 旧记录没有场景或支付方式时显示「未选择」，不自动猜测。
- 后续页面包含所选月份的完整账单明细，含原金额、报销状态和个人花销。

## 实现与验证（2026-09-06）

使用 ArkWeb 的本地 HTML 预览与 createPdf 生成 A4 PDF，内嵌图表，不使用在线图表服务。动态文本做 HTML 转义，并禁用页面脚本、文件访问和网络资源。PDF 生成及写入失败会提示重试；取消保存可继续选择月份或导出。

通过：

- `node tests/monthly-report.cjs`：跨月、部分/全额/结束报销、还款排除、类别/支付/每日金额核对、旧记录、闰月、空月份、文本转义。
- `node tests/reimbursement.cjs`：既有记账与旧数据兼容回归通过。
- DevEco 签名构建通过。
- 同一报表 HTML 的桌面 Chromium PDF 渲染：A4 两页，逐页检查中文、分类条形图、每日图表和明细分页，无重叠或乱码。
- USB 真机独立测试账本：打开月报，个人花销 95 元、原消费 195 元、已报销 100 元、还款 600 元与账本一致；切换空月份并切回，金额正确；系统保存窗口成功将 PDF 写入 Download，显示「可视化月报已保存为 PDF」；取消再次保存后恢复可操作。

限制：手机保存文件尚未独立读回逐页核对；PDF 版式检查使用相同 HTML 在桌面 Chromium 生成的 PDF。测试不写正式账本。

新版正式包已覆盖安装，原账单仍可见；正式环境导出菜单含 PDF 和 CSV 两个入口，检查后已返回首页，未更改原记录。

配色更新：两个分类图使用按子类固定的浅色渐变及同色色标（浅蓝、薄荷绿、淡紫、杏桃、浅粉、奶黄；未选择为灰蓝）。通过构建、月报统计回归和桌面 PDF 渐变渲染检查；已覆盖更新正式包并确认原记录可见。
