# Bill 记账 App · UI/UX 审查报告

- **审查对象**：Bill v1.0（HarmonyOS / ArkTS，深色主题）
- **审查方法**：Nielsen 十大可用性启发式原则 + WCAG 2.1 移动端无障碍要点 + 记账类应用用户流程基准
- **审查范围**：首页、记账页（收入/支出）、账单记录页、统计分析页
- **报告日期**：2026-09-01
- **涉及源码**：`entry/src/main/ets/pages/`（Index / RecordEditPage / RecordsPage / StatsPage）、`common/Theme.ets`、`common/BillStore.ets`

---

## 1. 现状信息架构

```
首页 (Index)
├── 记一笔收入 ──→ 记账页 (type=income)
├── 记一笔支出 ──→ 记账页 (type=expense)
├── 账单记录 ────→ 记录列表（按日期分组，可删除）
└── 统计分析 ────→ 月度统计（圆环图 + 每日支出柱状图）
```

层级浅（全部两级），这是优点；但首页同时承担"导航中心 + 月度摘要"两个职责，返回路径只有左上角的 `‹`。

## 2. 主要发现（按严重程度）

### P0 — 阻塞或高概率造成数据损失/误操作

| # | 位置 | 问题 | 影响 |
|---|------|------|------|
| P0-1 | 记录页删除 `×` ✅已修复（左滑删除+确认弹窗） | 点按立即删除，无确认、无撤销 | 误触即丢数据，违反"防错原则"。记账数据是用户资产，必须有后悔药 |
| P0-2 | 记账页备注输入框 | 页面底部已有自定义键盘，备注框仍会唤起系统 IME，小屏设备上 IME 会遮挡数字键盘和保存按钮 | 用户可能找不到保存按钮，流程中断 |
| P0-3 | 统计页圆环图 ✅已修复（改为支出占收入比） | 圆环把收入、支出画在同一总账里，圆心却显示"支出占比"，口径含混（支出 ÷ (收入+支出) 不是任何有意义的财务指标） | 数据误导。应改为"支出结构"或明确的收支对比 |

### P1 — 明显降低效率或可达性

| # | 位置 | 问题 | 影响 |
|---|------|------|------|
| P1-1 | 全局触控目标 | 返回键 `‹`（宽 40、无高度设定）、删除 `×`、日期 chips（高约 34vp）均小于推荐的 44×44vp | 误触率高，老年用户和单手操作困难 |
| P1-2 | 记账流程 | 保存后强制返回首页，无法"保存并再记一笔" | 连续补记多笔账单时每次都要重新进入，步骤翻倍 |
| P1-3 | 记录页 ✅已修复（点击条目进入编辑） | 只支持删除，不支持编辑；记错金额只能删了重记 | 高频痛点 |
| P1-4 | 视觉反馈 | 自定义键盘按键、各卡片均没有按下态（pressed state） | 点击无反馈，用户不确定是否点中 |
| P1-5 | 色彩语义 | 收入/支出仅靠绿/红区分（首页胶囊、统计图例） | 红绿色盲用户（男性约 8%）无法区分，需叠加文字/符号冗余编码 |
| P1-6 | 无分类体系 | 只有"收入/支出 + 自由备注"，统计只能到"每日支出"粒度 | "钱花在哪"这个记账核心问题回答不了，备注自由文本无法聚合 |

### P2 — 体验优化项

| # | 位置 | 问题 |
|---|------|------|
| P2-1 | 首页 | 本月结余数字无趋势参照（环比上月 ±%），大数字缺少上下文 |
| P2-2 | 记录页 | 无搜索/按月筛选；无单日小计 |
| P2-3 | 统计页 | 只有"每日支出"一种视角，缺收入趋势、周末/工作日对比等 |
| P2-4 | 全局 | ~~仅深色主题~~ ✅主题已跟随系统；硬编码中文字符串，未抽离到资源文件 |
| P2-5 | 数据安全 | 无导出/备份（卸载即丢），无预算提醒 |
| P2-6 | 空状态 | 记录页空状态仅一行文字，没有引导按钮 |

## 4. 可执行改进计划

### 第一阶段：安全与纠错（半天）
1. 删除改为左滑 + 确认弹窗（或 Snackbar 撤销）——`RecordsPage.ets`
2. 统计页圆环口径修正：收入/支出对比改为双弧独立展示，或改为支出占比（基于支出总额）

### 第二阶段：效率（1 天）
3. 记账页加"保存再记一笔"；保存后 Toast 带撤销
4. 记录页条目点击进入编辑（`BillStore` 加 `update` 方法，记账页支持编辑模式）
5. 全部触控目标放大到 ≥44vp；按键/卡片加 `stateStyles` pressed 反馈

### 第三阶段：能力补全（1–2 天）
6. 引入分类体系（预设分类 + 图标，支出必填）；统计页圆环改为按分类拆分
7. 备注框聚焦时布局避让 IME（或改为底部弹出输入）
8. 记录页加月份筛选与日小计

### 第四阶段：打磨（按需）
9. 首页加环比趋势；CSV 导出/备份；浅色主题；字符串资源抽离

---

## 5. 度量建议

上线/试用后关注：记一笔的平均耗时（目标 <15 秒）、误删率、连续记账占比、7 日留存（记账类应用的核心指标是"坚持记"，一切降低记账摩擦的改动都直接服务于它）。

---

*本报告基于源码静态走查与启发式评估，未包含真实用户测试数据；建议在第二阶段完成后找 3–5 名目标用户做一次 30 分钟可用性测试。*
