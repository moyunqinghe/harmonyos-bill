# 个人花销与报销

日常记账只填金额、日期，备注和凭证可选。支付方式、具体信用卡、账单日和还款日不必填写。

- 消费按发生日期记支出；还款本金和自己账户间转账仅留记录，不计收支。
- 新支出可勾选“这笔需要报销”。已保存的支出，在编辑页进入“登记报销 / 管理报销”。
- 报销页填写累计已到账金额、最近到账日期。支持全额到账快捷填写、部分到账，以及“报销已结束”。金额为 0 表示尚未到账。
- 个人花销 = 原消费金额 − 累计实际到账报销。报销归属于原消费月份，不增加到账月份收入；因此历史月份的个人花销可能随报销更新。
- “待报销”筛选跨月份显示尚未结束的记录。报销已结束但未全额报销的差额仍计个人花销。
- 明细保留原消费金额，日汇总和月度图表使用个人花销。首页额外显示原消费和已报销金额。
- CSV 保留原有四列，并追加报销状态、累计已报销、最近到账日期和个人花销。此版本保存累计金额及最近日期，不保存多次到账事件明细。

## 数据兼容

沿用 `bill.db` 与原有 `bills` 表。新增 `bill_reimbursements` 附表，用原账单 ID 关联，初始化不改写历史账单。对极早期无图片列的账本，仅补充默认空的图片列。账单与报销写入在同一事务提交，失败回滚。

覆盖安装使用现有包名和签名，DevEco 运行配置需勾选“保留应用数据”。不要卸载已有 App。旧记录不会根据备注自动分类或标记报销。

## 验证

`node tests/reimbursement.cjs` 使用 DevEco 自带 TypeScript 编译器执行当前 ArkTS 存储代码，以临时内存 SQLite 适配 HarmonyOS RDB。覆盖旧库兼容、并发初始化、待报销、部分/全额到账、重复保存、非法金额、事务失败回滚、重新打开后的持久化、跨月统计、还款排除和关联清理。该测试不连接手机账本，也不能替代真机 UI 验证。
